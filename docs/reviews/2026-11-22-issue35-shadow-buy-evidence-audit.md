# Issue 35 รอบ 44 — ตรวจหลักฐาน BUY ก่อนสรุปเดินเงา

ผลจับคู่ BUY ที่ปิดแล้วอาจเกิดจากสถานะค้างหรือทุนต่างกัน เมื่อกรณีทดสอบให้ native ปิด BUY และ range20 ปฏิเสธที่สัญญาณเดียวกันด้วย `busy` ตัวรันเดิมคืน `resolved=true` แสดงว่าผลของไม้ที่รับทราบแล้ว แต่ยังระบุไม่ได้ว่ากฎ BUY ที่ปรับเป็นเหตุให้ต่างกัน

เพิ่มตัวอ่านผลเดินเงาแยก โดยผูกการรับไม้กับ ledger ที่ quote เข้าและจับคู่การตัดสินใจตามเวลาแท่งปิด เก็บเหตุผลรับหรือปฏิเสธ ผลปิด และสถานะค้าง ตรวจความต่างของแผน BUY และการพัก BUY จากข้อมูลเหตุการณ์ที่ตัวรันบันทึกไว้ กรณีไม่มี event ของอีกบัญชีแสดงตามที่เห็นในข้อมูล แล้วตรวจสัญญาณเพิ่มเติมก่อนสรุปสาเหตุ

## ผลทดสอบกับข้อมูลย้อนหลัง

ทำซ้ำช่วง พ.ย. 2022–24 บน Mac ใช้ทุน $200, 0.01 lot และ Exness Bid/Ask ตามกติกาเดิม แยก base+swap และ stress+swap ทั้ง native, ชุดก่อนพัก BUY และ range20 ให้ ledger ตรงกับผลที่บันทึกไว้ครบทั้งหกบัญชี

- 27 เม.ย. 2023 เวลา 20:00 น. ไทย range20 พัก BUY ตลาดแกว่งโดยยอดปิดของกลุ่มอยู่ที่ −$22.39 base และ −$22.50 stress ชุดก่อนพักรับสัญญาณเดียวกันและปิด −$9.07 base และ −$9.21 stress
- ณ เวลาเดียวกัน ฝั่ง native ไม่มี event BUY ในชุดที่บันทึกไว้ จึงแสดงผลพัก BUY ของ range20 แยกจากหลักฐานเปรียบเทียบ native
- เทียบ native ใน stress พบ 27 เวลาแท่งปิดที่บัญชีหนึ่งมีผล BUY และอีกบัญชีติดกฎสถานะหรือความเสี่ยง พบอีก 2 เวลาที่ตัวบล็อกคือกำไรเดือนถึงเป้า และ 87 เวลาที่มีผล BUY จากฝั่งเดียวโดยไม่มี BUY event อีกฝั่ง ตัวรายงานเดิมมี 116 แถวที่จบผลแล้วใน stress
- ผลย้อนหลังตัวอย่างล่าสุดไม่มี BUY ในทั้งสองต้นทุน ตัวตรวจคืนรายการ BUY ว่างทั้งสองฝั่ง

เมื่อมีผล prospective ให้ตรวจ ledger คู่ เหตุผลที่บัญชีตัดสินใจต่างกัน และผลปิด BUY ตามที่ตกลงกับผู้ใช้ก่อนเสนอ Demo ตัวตรวจเพิ่มเติมอ่านผลอย่างเดียว ชุดเดินเงาที่ล็อกไว้ผ่าน checksum
