## Leak D test — FAIL, keep current rule

Protocol `protocol-D.json` (frozen before running). D1 is one predeclared logic change: count a loss
(daily quota + cooldown) only if net < −0.5 × initial risk. BE exits are ≥ −0.33R and full SL ≤ −1.0R,
so D1 separates them cleanly. The test covered 3 windows × base/stress × $313/$200 (12 cells), with a
no-regression gate against native.

Result: **FAIL in 10 of 12 cells.**

| Window | native → D1 net, base $313 | base $200 | stress $200 |
| --- | --- | --- | --- |
| 2024-09..2026-10 | 1923.60 → 1807.89 | 1945.33 → 1657.45 | 1471.87 → 1337.09 (DD 37.7 → 40.0) |
| 2023-01..2024-08 | −262.83 → −265.24 | −175.73 → −177.34 | equal |
| 2020-2022 | −294.35 → −294.70 | −182.12 → −180.49 | −179.96 → −181.97 |

Attribution (discovery base $200): D1 admitted 9 extra trades after BE scratches. Those lost −$60.63 with
1 win in 9. Because only one position is allowed, they displaced 9 native trades worth +$227.26.
Common trades are identical. The "BE = loss" rule acts as an accidental chop guard: after a BE
scratch, later same-day signals have tended to lose.

Sample is small (9 trades). Under the owner's no-regression rule this is still a clear NO_CHANGE.
The residual cost of BE exits ending negative is about $39 per two years, which is small. Making the
BE price swap-inclusive is possible but not worth the runtime complexity now.

## Leak B test — tick-level BE trigger

Each test used a frozen protocol (`protocol-B.json`, `protocol-B2.json`) and a parity engine: the patch
with an unreachable trigger had to equal native in every cell, and it did. Tick BE is an upper bound,
because live runtime would need sub-bar polling. The windows and gates are the same as for D.

**B1, tick BE at 1R on both sides: FAIL in 9 of 12 cells.** DD improves a lot (2024-26 base $313:
30.26 → 23.22%), but net falls (base −$35, stress −$129).

Root cause (`rc_B.py`, base $313, matched trades native → B1):

| Side | SL → BE saved | TP → BE winners scratched | Direct |
| --- | --- | --- | --- |
| BUY | +143.42 (11) | −55.35 (2) | +88 |
| SELL | +268.13 (9) | −308.37 (9) | −40 |

The SELL TP at 1.35R is only 0.35R beyond the 1R trigger. SELL winners often touch 1R intrabar, pull
back to entry, and then reach TP. The bar-close check never sees that pullback; tick BE scratches the
trade. BUY's TP at 3R is far from the trigger, so few BUY winners are scratched.

**B2, debug iteration: tick BE at 1R for BUY only, SELL unchanged.** It passes 10 of 12 cells, including
all 6 cells at $313 (live size).

Root cause of the stress $200 failure (`rc_B2.py`):
- Direct BUY effect is still positive: +122.35 saved, −95.99 scratched.
- One native BUY TP (−$99.74) was missed because a B2 trade occupied the single slot.
- Cap rejections went from 5 to 10.
- B2's max DD falls early, on 2025-01-20, while the account is still small ($265.94 peak → $158.21).

At $200 the 10% cap path dominates, as in the 2026-11-02 root cause. The failure is not a systematic
BUY effect. The 2020-22 failure is about $1.

Caveats:
